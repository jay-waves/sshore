# bbolt 迁移交接

## 当前状态

- 基线提交 `5e7bfc8` 包含清单读取与历史写入解耦的改动。
- 此次提交保留停止时的 bbolt 实验。账号 daemon 启动时打开
  `connections/participation.db`，关闭时释放句柄。远端任务观测按主机和任务
  ID 存储。更新和删除按键执行，刷新在同一事务内扫描对应主机。
- 第一次建 bucket 时，在同一事务中导入旧 `participation.json`。旧文件保留，
  bucket 存在即跳过导入，避免重启后恢复已删除的记录。
- `list` 和 `pstree` 用短读事务取观测记录。活任务仍在 daemon 注册表里，
  最近连接和最近分离记录仍用现有 JSON。此轮以实现简洁为准，允许清单直接读库。

## 继续前核对

- [participation.go](../participation.go) 目前在校验私有路径前用 `O_CREATE`
  打开数据库路径。应先校验已有文件，新建时用 `O_EXCL`，避免跟随失效链接创建目标。
- 新键仍保留 4096 条上限。当前实现通过 `Bucket.Stats()` 计数，需要核对这次遍历
  是否值得保留。旧 JSON 的 1 MiB 限制只用于导入，数据库不再维护整表字节数。
- 子代理报告较早版本通过 Windows 的标准 Go 测试。收到停止指令前又做了一轮删减，
  此提交的最终版本没有重新运行测试，Linux 和 Windows 远程 CI 也尚未运行。
- 恢复时先用 `go run ./scripts go test ./...` 验证，重点核对一次导入、重启后
  删除仍生效、陈旧附件不能覆盖新状态、数据库不可用时活任务仍可列出。
